# PostgreSQL inspection

Run `forgeschema inspect SCHEMA_NAME` with DATABASE_URL supplied through the environment. The command supports PostgreSQL major versions 16 and 17, prints canonical version 1 schema JSON and exits with code 1 on inspection errors or code 2 for usage errors. It does not print a partial snapshot. A nonexistent schema is an error; an existing empty schema produces tables: []. The command has a 30-second deadline. Connection/query failures are sanitized to avoid exposing connection credentials; unsupported-object errors identify the object and feature.

The Go API is postgres.Inspect(ctx, db, schemaName). It opens one READ ONLY, REPEATABLE READ transaction with catalog-only search_path. It reads catalog metadata only, never application rows. The caller owns the database connection pool and supplies a deadline. The API returns underlying database errors for programmatic diagnosis; callers must avoid logging credentials. Standalone inspection is a snapshot, not a lock protecting a later migration against drift or concurrent DDL.

One existing schema is managed. All ordinary tables and their live columns, primary keys and indexes in that schema must fit SCHEMA.md; unsupported identifiers and types fail normalization. Primary key backing indexes are not duplicated in ordinary indexes. The key constraint must have the deterministic TABLE_pkey name. Default column collations and default btree operator classes/order are accepted. Dropped column slots are ignored. Physical column order is nonsemantic, while composite key and index order is preserved.

Inspection rejects views, materialized views, sequences, foreign tables, partitions, inheritance, unlogged tables, nonheap table storage, custom table/index options or tablespaces, row security, policies, rules, user triggers, defaults, identity/generated columns, nondefault column collations/storage/compression and unsupported types. It rejects unique/check/foreign/exclusion/deferrable constraints, custom primary key names, unique/partial/expression/include/non-btree/descending/custom-opclass indexes, invalid indexes, clustered/replica-identity indexes and nondefault replica identity. It also rejects schema-owned custom scalar types/domains, functions/procedures, collations, conversions, extended statistics and extension-owned relations.

Ownership, grants, comments, optimizer statistics targets, data contents and physical column positions are outside the canonical contract and do not affect its fingerprint. Objects in other schemas are not enumerated as part of this snapshot. Database-wide objects, event triggers, publications, external dependencies and server configuration are outside its scope. A successful inspection does not certify that future DDL is executable or that it has no effects outside the managed schema; migration preconditions and dependency checks belong to later stages.

The integration suite creates disposable schemas, executes the populated customer fixture, compares three inspections with desired YAML, checks ordered composite keys/indexes and all supported types, rejects unsupported structures, checks a restricted role and cancellation, and exercises successful CLI inspection. The suite requires a dedicated disposable database whose test user may create schemas and roles. Production inspection requires only the catalog visibility needed to read the selected metadata; it does not need application-table SELECT privileges.
