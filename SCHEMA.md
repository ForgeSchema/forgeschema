# Schema contract, version 1

A document contains required version: 1, a schema name and a tables sequence. Use tables: [] for an empty managed schema. A table has a name, a nonempty columns sequence, optional primary_key column names and optional indexes. An index has a schema-wide unique name and a nonempty ordered columns sequence. A column has name, type and optional nullable; omitted nullable means false (NOT NULL). Primary key columns must be nonnullable. Primary key index names are reserved as TABLE_pkey and must fit 63 bytes without collisions. Composite primary keys and index column order are significant. At most 1600 columns per table and 32 columns per key or index are accepted.

Names are lower-case ASCII letters, digits and underscores; they must start with a letter or underscore and fit PostgreSQL's 63-byte limit. Names beginning pg_ or forgeschema_ and information_schema are reserved. This deliberately restricted naming policy will also be used by the inspector; identifiers outside it are unsupported, not silently renamed.

Types: smallint, integer, bigint, text, boolean, uuid, date, timestamp without time zone, timestamp with time zone, jsonb, bytea, real and double precision. PostgreSQL aliases int2, int/int4, int8, bool, timestamp, timestamptz, float4 and float8 normalize to those types. Type spelling is case-insensitive and whitespace is normalized. No parameterized types, defaults, identity/serial, generated columns, arrays, enums, domains, collations, unique/foreign/check constraints, expressions, partial indexes or index options are accepted yet.

The YAML reader rejects unknown and duplicate fields, null values, multiple documents, custom tags, anchors, aliases and scalar coercion (quote-looking booleans and numbers do not become booleans or numbers automatically). The input limit is 1 MiB. Documents constructed directly in Go are validated too. Canonical JSON sorts tables, columns and indexes by name but preserves the ordered columns in keys and indexes. Physical column order is outside this contract. SHA-256 fingerprints cover canonical JSON, including the contract version. Fingerprints detect representation differences; they are not signatures or plan authorization.

Explicit rename intent is supplied through the separate versioned mapping file described in PLANNING.md; schema files themselves have no rename field. Unsupported YAML fields fail today. Read-only PostgreSQL 16/17 inspection maps supported catalog objects to this contract and rejects unsupported structures. Defaults remain unsupported and are rejected instead of normalized away. Offline SQL generation is available through the planner. Migration execution does not exist in this checkpoint. See INSPECTION.md.
